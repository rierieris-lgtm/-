## 決まったこと

### 1. 自動実行はしない。自分のタイミングで呼びかける

**理由**: 決まった時間に自動でログを取る設定にしても、その時間にパソコンを閉じていたら動かない。

> ゆかぴ「例えば5時とかにした時に、そのタイミングでパソコン閉じちゃってたらダメじゃない。……そういう意味では自分のタイミングの方がいいかもしれない」

**補足（技術的な整理）**:
Claude Codeの定時実行は、パソコンが起動していてClaude Codeが動いている必要があります。ノートPCを閉じる運用なら、自動化は「動いたり動かなかったり」になり、それが**いちばん信用できない状態**です。

将来もし自動化したくなったら、選択肢は2つ:
- クラウド側で動かす（Claude Codeのウェブ版／リモート環境）＝ PCを閉じていても動く
- 諦めて手動のままにする ＝ 確実

**現時点の結論: 手動。**「おやすみ」と声をかけたら動く、が正解です。

---

### 2. 「日記つけて」に感情ヒアリングを混ぜない。「おやすみ」に寄せる

**理由**: 毎回日記をつけるたびに感情を聞かれると面倒になり、続かない。

> ゆかぴ「毎回日記つけてって言ったタイミングでそれ聞かれても面倒くさいじゃん。……例えば今みたいに『おやすみ』っていう言葉に対してだけそういう感情を聞く」
> 「その『おやすみ』っていう言葉には、その日の出来事をまとめるっていう作業と、その感情を聞いていくみたいなものが込められてる」

**役割分担**:

| 呼びかけ | やること |
|---|---|
| 「日記つけて」 | その時点の作業ログを淡々と残す。感情は聞かない |
| **「おやすみ」** | ①その日の出来事をまとめる ②感情を聞く ③他に残したいことがあれば書かせる |

→ 実装は [../skills/oyasumi/SKILL.md](../skills/oyasumi/SKILL.md) にあります。

---

### 3. 何が保存されているか、最初のうちは毎回中身を確認する

これがゆかぴの指摘でいちばん重要なものです。

> ゆかぴ「とりあえずやってみて、残ってるかどうか確認するっていうのを最初のうちやった方がいいかも。どんなことが残されてるか」
> 「日記つけてって書いた『日記をつけました』とかだけが残されてても意味ないじゃん」

**チェックする観点**:

- [ ] ファイルが実際に作られているか（言っているだけではないか）
- [ ] 中身は「作業をした」ではなく、**何をどうしたか**が書かれているか
- [ ] 後で読み返して、その日を思い出せるか
- [ ] 検索できる形になっているか（日付、キーワード）
- [ ] 感情が入っているか（`おやすみ` の日のぶん）

**確認のしかた**: 保存先のフォルダを直接開いて、ファイルを目で見る。AIに「ちゃんと保存できた？」と聞くと「できました」と返ってくるので、それでは確認になりません。

> 現在の保存先は `diary` リポジトリ（日記保存BOX、2026/7/19作成）と思われます。

---

### 4. なぜ感情を残すのか

チャットのタブごとの記録は、仕事の話ばかりで自分の感情が入らない。それだけだと「仕事の記録としての日記」にしかならない。

**感情ログの使い道（ゆかぴ）**:
- 文章を作るときに、そこから拾ってこられる
- **作りたい講座の壁打ちをClaude Codeでするときに役立つ**

**→ これは本当にそのとおりで、講座の企画は「自分が何に困り、何に腹を立て、何を良いと思ったか」から出てきます。**
7/16の会話がまさにそうでした。詐欺案件への怒り、「実際そんな使わないじゃん」という違和感、この2つが講座のコンセプトの芯になっています。感情ログはその素材です。

## CLAUDE.md とスキルの整理

Rieの理解が正確なので、そのまま書いておきます。

| | 役割 | 例 |
|---|---|---|
| **CLAUDE.md** | プロジェクト全体に対する指示。常に読まれる | 「日本語で話す」「私の仕事は〇〇」「保存先は〇〇」 |
| **スキル** | 一つ一つの作業に対する指示。その作業のときだけ読まれる | 「おやすみ」「日記つけて」「投稿の下書き作って」 |

> Rie「大きいのも決めとかなきゃいけないし、これ一個に対してはこういうルールだよっていうのを決めてく。その一個一個がスキル」

**CLAUDE.md を触るのが怖いという話について**:

> ゆかぴ「そこも触ろうとしたけど、あんまりいじらない方がいいかなと思ってやめちゃった。せっかく作ってくれたのを壊しちゃってもね。……セキュリティとかのことががっつり入っているのかなと私は思っている」

安心材料として:
- CLAUDE.md は**ただのテキストファイル**です。壊しても、消しても、AIが動かなくなることはありません
- セキュリティ機能はCLAUDE.mdではなく、Claude Code本体の側に入っています。CLAUDE.mdを編集してもそこは変わりません
- 怖い場合は、編集する前にファイルをコピーして `CLAUDE.md.backup` として残しておけば、いつでも戻せます
- Gitで管理していれば、そもそも全部の変更履歴が残るので元に戻せます

**つまり、触って大丈夫です。**

## スキルの育て方（今後）

7/16時点でRieは「今言ってくれたやつをいろいろ入れて、スキルがすごい充実してきたよ」と言っています。この調子で、**使っていて面倒だと感じた瞬間**にスキルを足すのがいちばん自然です。

追加すると良さそうなもの:

| スキル案 | きっかけになりそうな場面 |
|---|---|
| `おやすみ` | 1日の終わり（実装済み） |
| `週まとめ` | 木曜のローンチラボ前に、1週間の進捗を自動でまとめる |
| `投稿ネタ出し` | 日記と感情ログから、Instagram投稿のネタを提案させる |
| `壁打ち` | 講座の企画を相談する。感情ログを参照させる |
| `案件チェック` | 応募しようとしている案件が怪しくないか、ゆかぴの見分け方7項目でチェックさせる |

最後の `案件チェック` は、ゆかぴの実体験がそのままチェックリストになるので、作れば**講座の教材にもなります**。
